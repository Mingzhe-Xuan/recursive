## 1. 目标、命名与范围

使用 CGCNN、Matformer、iComFormer 三个 backbone，分别开展以下实验：

1. 从原始晶体结构训练性质预测模型，建立第 0 轮基线。
2. 使用该轮验证集选出的 checkpoint，在固定版本的整个 JARVIS-DFT 结构库上推理，
   缓存原子隐藏特征。
3. 将缓存特征通过额外线性层映射到下一轮模型的输入维度，训练一套新权重。
4. 使用新权重消费上一轮缓存，生成下一份缓存，重复执行。
5. 绘制每个 backbone、每个性质任务的 MAE 随循环轮数的变化曲线。

工作名称采用 **Sequential Self-Evolution**，也可称 **Sequential Test-Time Scaling**。
方法同时增加离线监督训练计算量与新结构的串行推理计算量；报告时分别核算二者。
这里的 self-evolution 使用原有训练集真实标签，不要求生成伪标签；测试时不更新权重。

本计划独立于 [plan_1.md](plan_1.md) 中冻结同一 backbone、重复已有 block 的方案。
此处每轮训练新的阶段模型，已完成阶段冻结，不跨阶段反向传播。

用户已确定三个 backbone 和线性维度适配。本文的轮数、seed、初始化和训练预算为
待实施的默认配置，必须在正式实验前写入版本化配置；不得根据测试曲线事后改动。
本次交付仅为计划，不表示下述模块、数据、环境或实验已经完成。

### 2.3 全库缓存的用途

对固定版本的整个有效结构库做前向推理，缓存包括训练、验证、测试及当前任务无标签的结构。
推理使用 `eval()` 和 `no_grad()`，不更新 BatchNorm 或其他状态，不读取标签。
训练下一轮仍只对该任务训练集合计算监督损失；无标签结构仅获得特征，不自动加入训练。

缓存按 `(backbone, task, seed, round)` 隔离。不同任务 checkpoint 的特征不得互相替代，
即使输入结构相同。图拓扑等不依赖任务和权重的原始几何缓存可以复用。

## 3. 逐阶段循环的数学定义

令结构为 \(x=(Z,R,L)\)，任务为 \(t\)，固定几何上下文为
\(G_b(x)\)，其中 \(b\) 表示 backbone。几何包含周期邻居、镜像、距离及该模型所需角度。
令 \(A_b(x)\) 为原始原子描述符，每个原子对应一行。

阶段模型由消息传递编码器 \(F_{b,t,r}\) 和图级预测头 \(D_{b,t,r}\) 组成。
缓存边界固定在最后一层消息传递之后、pooling 之前。

### 3.1 第 0 轮：原生基线

\[
H_{t,0}(x)=F_{b,t,0}(A_b(x),G_b(x)),
\qquad
\hat y_{t,0}(x)=D_{b,t,0}(H_{t,0}(x)).
\]

训练完整原生模型，用验证集选出 checkpoint，然后生成第 0 轮全库缓存 \(H_{t,0}\)。
此处轮数从 0 开始，缓存编号与产生它的阶段编号一致。

### 3.2 第 r 轮：缓存输入与新权重

对 \(r\geq1\)，引入逐原子共享的可训练仿射投影：

\[
P_{b,t,r}(h)=W_{b,t,r}h+c_{b,t,r},
\qquad
P_{b,t,r}:\mathbb R^{d_h}\rightarrow\mathbb R^{d_{\mathrm{in}}}.
\]

其中 \(d_{\mathrm{in}}\) 是该 backbone 原始原子输入描述符的宽度。
投影输出送入原生 atom embedding，保留原生消息传递与预测头结构：

\[
H_{t,r}(x)=F_{b,t,r}
\left(P_{b,t,r}(\operatorname{stopgrad}(H_{t,r-1}(x))),G_b(x)\right),
\]

\[
\hat y_{t,r}(x)=D_{b,t,r}(H_{t,r}(x)).
\]

每轮使用相同任务的真实训练标签，优化当前阶段的投影、编码器与预测头参数；
上一轮缓存固定，历史模型参数与 buffer 不变。当前轮不接收历史阶段的梯度。
主实验不额外拼接原始原子特征或前几轮特征；此类信息保留方式作为独立消融。

主方案每轮随机初始化完整阶段模型及线性投影，重新创建 optimizer 和 scheduler。
各轮 seed 从全局 seed、backbone、任务和轮数稳定派生，并保存实际值。
继承上一轮模型权重列为消融：可兼容参数继承，投影与优化器状态如何处理必须明确记录；
不得把两种初始化结果混成同一条曲线。

### 3.3 推理与历史链

第 r 轮的输入必须来自同一实验链的 \(H_{t,r-1}\)，不能把第 r 轮 checkpoint
单独作用于原始输入，也不能每轮都重新使用 \(H_{t,0}\)。

对未缓存的新结构，先执行第 0 轮，再按顺序执行第 1 至 r 轮，共经过 r+1 个阶段模型。
所有阶段的权重、投影、归一化状态与构图配置均属于最终可部署模型。
对已经有缓存的结构，可以从对应边界恢复，但须报告这是缓存条件下的计算成本。

## 4. 三个 backbone 的特征接口

统一主实验选择 **原子特征循环**：缓存节点隐藏特征，几何输入由原始结构固定提供。
每一阶段重新计算本阶段权重相关的边/角 embedding；不复用上一阶段学到的边 embedding。
这是一项显式实验设计，不把它称为沿用上一模型全部动态状态。

| Backbone | 缓存内容 | 固定或重新提供的几何 | 接入位置与审计重点 |
| --- | --- | --- | --- |
| CGCNN | 最后一层 crystal convolution 后的原子特征 | 周期邻居索引、原始距离展开、晶体归属 | 投影后进入原生 embedding；保持邻居 padding/mask 语义 |
| Matformer | 最后一层节点更新后、pooling 前的标量特征 | 周期图、距离和晶格相关描述 | 投影后进入原生 embedding；固定周期镜像与边顺序 |
| iComFormer | 最后一层节点更新后、pooling 前的不变标量特征 | 官方周期图及距离/角度描述 | 仅使用 iComFormer 分支，逐项审计节点/边/角索引 |

三个模型分别锁定官方源码提交、依赖版本与原生训练配置。
先复现其原生 forward，再实现不改变原生路径的特征导出接口。
不预设三者隐藏宽度相同；每个配置显式保存输入/隐藏维度和投影 shape。
若审计发现拟选缓存边界不满足上述定义，先修订接口与计划，禁止通过隐式 reshape 通过检查。

缓存始终按结构保存原子顺序，主键包含稳定结构 ID。晶胞规范化、原子重排或重新构图
可能改变索引，因此缓存需要绑定结构、原子顺序和构图配置的 hash。

## 5. 缓存、checkpoint 与恢复协议

使用分片张量文件加 manifest，避免一次性把全库节点特征放入内存。
首轮主实验缓存采用 float32；降低精度作为后续独立实验。
每片保存结构 ID、原子数、原子区间偏移和节点特征，不保存标签。

缓存 manifest 至少包含：

- schema 版本、backbone、task、seed、round、特征边界及 shape/dtype；
- 数据快照 hash、结构 ID 集合 hash、原子顺序/构图配置 hash、split hash；
- 本轮 checkpoint SHA-256、前一轮缓存 manifest SHA-256、完整配置及代码提交；
- 分片文件名、结构数/原子数、字节数、SHA-256，以及成功与失败 ID 清单。

写入先使用临时文件，校验后原子发布；完整性验收通过才创建完成标记。
下一轮只消费匹配且已完成的缓存，不接受半成品、错任务、错轮数或错 checkpoint。
CGCNN 当前实现采用基础 `cache/manifest.json` 与补充 `cache_provenance.json` 组成交付 manifest：
基础文件保持缓存身份稳定；补充文件内联完整配置、来源、成功/失败 ID 及逐片字节数等审计字段，
引用基础文件 SHA，并由根 `chain_manifest.json` 以 SHA 引用。审计需重验全部分片，
不能通过就地改写基础 manifest 破坏已训练阶段绑定的前驱缓存身份。
断点恢复必须验证以上依赖，再复用已校验分片；不能只凭文件存在就跳过计算。
缓存失败的结构若属于某轮训练/验证/测试集合，该轮不能按完整任务验收。

每轮训练完成后保留验证集最优 checkpoint、训练配置、指标与预测结果。
缓存采用 eval 模式，验证从缓存读取与直接串行推理的结果在明确容差内一致。
主模型链的历史 checkpoint 必须保留；中间缓存仅在确定可重建且下游完成验收后才可清理。

运行产物统一置于被忽略的 `outputs/self_evolution/` 或服务器任务专用持久目录：

```text
outputs/self_evolution/<run_id>/
  dataset/
  graphs/<backbone>/<graph_hash>/
  <backbone>/<task>/seed_<seed>/
    round_000/
      config.json
      checkpoints/
      cache/
      predictions/
      metrics.json
    round_001/
    chain_manifest.json
  reports/
```

数据、特征缓存、checkpoint、日志、分片及批量预测不进入普通 Git。
小型来源 manifest、配置和必要的划分元数据单独版本管理，并检查大小和忽略规则。

## 6. 实验矩阵与公平对照

### 6.1 主实验

- Backbone：CGCNN、Matformer、iComFormer，各自独立循环，不跨模型交换特征。
- 任务：第 2 节锁定的全部回归任务，不以 5 个常用任务代替。
- Pilot：先用 CGCNN 的 formation energy 跑通第 0、1 轮，再验证完整串行链。
- 首批正式轮数：\(r=0,1,2,3,4,5\)，每个阶段的额外循环含义一致。
- Pilot 使用 seed 123；正式实验使用 42、123、2026，保留 pilot 的独立标识。
- 三个 backbone 全部完成原生基线与两轮闭环后，再逐任务扩展完整矩阵。

每个 backbone/任务先锁定第 0 轮训练协议，包括 loss、batch size、学习率、scheduler、
最大 epoch、验证频率、early stopping、标签变换与 pooling。
后续轮数沿用同一预算与选择规则，报告线性投影新增的参数量。
不要求三个不同架构参数量相等；跨架构比较同时报告各自计算量。

轮数上限在正式测试前固定。出现 NaN/Inf、数据/缓存不完整或资源不足时停止相应链，
保留失败原因与已完成结果，禁止用失败点填零或伪造 MAE。
若需要扩展到更大轮数，先登记新实验协议；不能根据测试曲线决定是否继续。

### 6.2 必要对照

1. **第 0 轮原生模型**：提供每个任务、backbone、seed 的标准基线。
2. **原始输入重新训练**：每次仍使用原始特征，保持与单阶段相同训练预算，
   用于估计随机训练波动，区别特征循环的收益。
3. **累计训练预算对照**：原生模型继续使用原始输入，给予与前 r+1 个阶段相近的
   累计训练 FLOPs 或优化步数；预先指定主匹配指标并同时报告 GPU 时间。
   scheduler 与验证选择规则也要预先定义，不能仅把 epoch 数乘上轮数后省略差异。

在资源允许且主实验可重复后，开展以下消融：

- 随机初始化下一阶段 versus 继承上一阶段权重；
- 仅缓存特征 versus 缓存特征与原始原子描述符拼接；
- 相同累计推理计算量的更深单模型，检验逐阶段训练与直接增加深度的区别。

不假设 MAE 随轮数单调下降。记录改善、持平、退化和训练失败，均作为实验结果。

## 7. MAE 曲线、轮数选择与计算量报告

对每个任务，在原始物理单位下计算 train/validation/test MAE。
标签若训练时有缩放或变换，必须先还原，再计算并报告误差。

固定轮数实验预先约定报告全部 \(r=0\ldots5\) 的测试曲线；训练期间不使用这些测试结果
调整轮数、超参数、checkpoint 或任务范围。实现上先完成整条链的训练和验证选择，
再由独立汇总作业生成测试结果与曲线。
最佳轮数 \(r^*\) 仅由验证集选择，另报告其测试 MAE 与第 0 轮差值。

交付图表包括：

1. 每个任务一张轮数曲线，比较三个 backbone，展示 seed 均值与标准差。
2. 每个 backbone 一张任务×轮数热图，使用相对本模型第 0 轮的 MAE 变化。
3. MAE 对累计训练 GPU 时间/FLOPs、累计串行推理时间/FLOPs 的曲线。
4. 任务覆盖表：样本量、划分、单位、完成轮数、最佳验证轮数和失败原因。

定义相对改善为

\[
I_{b,t,r}=\frac{\operatorname{MAE}_{b,t,0}-\operatorname{MAE}_{b,t,r}}
{\operatorname{MAE}_{b,t,0}}.
\]

正值表示改善；若基线为零，不计算该比值，报告绝对变化。
不同单位的任务不直接平均绝对 MAE。跨任务汇总报告改善任务比例、相对改善中位数和分布，
同时公开有效任务数，不把未完成任务算作成功。

训练成本包含所有历史阶段训练与全库缓存生成；部署成本包含历史链全部 forward，
不只测最后阶段。分别报告冷启动构图、已有几何缓存、已有特征缓存的情形。
计时记录设备、batch size、warm-up 和 CUDA 同步规则，避免异步计时失真。

| cache | eval checkpoint、结构批次、上一轮 manifest | 完整且可验证的分片缓存 |
| training | 当前轮输入、训练/验证划分、预算配置 | 验证集最优 checkpoint |
| pipeline | run 配置、历史链 manifest、完成标记 | 有依赖关系的阶段状态与推理结果 |
| evaluation | 各轮预测、标签、计算统计 | MAE 表、曲线、任务覆盖及失败报告 |

backbone 统一暴露 `forward_native`、`encode_nodes`、`forward_from_features`；
第 0 轮 `forward_native` 必须与官方实现数值一致。
旧的冻结工具可在接口明确时复用，但不能把当前阶段模型也永久设为冻结。

## 9. 测试与验收计划

每个实现单元开始前在 [test.md](../agents/test.md) 登记具体测试与预期。

| 范围 | 必须验证的行为 |
| --- | --- |
| 数据与划分 | ID 唯一、集合不交叉、缺失值规则正确、训练统计不读取验证/测试标签 |
| 原生复现 | 三个 backbone 的第 0 轮 wrapper 与固定官方实现一致，记录 dtype/设备/容差 |
| 特征接口 | shape、原子顺序、ID、图索引和投影维度匹配；投影可训练且梯度有限 |
| 阶段冻结 | 当前阶段参数可以更新；历史参数、梯度、buffer 和缓存均不发生变化 |
| 缓存与恢复 | 分片回读一致；错任务/错轮数/错 hash 被拒绝；中断产物不能作为完整输入 |
| 串行链 | 直接执行 0→1→2 与逐轮缓存路径的最终预测在预设容差内一致 |
| 数据隔离 | 修改验证/测试标签不改变训练输入缓存或训练标准化统计 |
| 预测与指标 | 原始单位 MAE 正确、相对改善方向正确、失败轮数不会被填零 |
| 可复现性 | 相同配置可恢复，记录非确定性算子及容差；恢复不重复使用过期缓存 |

先进行小图/小样本 CPU 测试，再通过 Slurm 做真实晶体 smoke test 和 GPU 验收。
不同 batch size 的 eval 缓存与逐结构结果应一致；不得把训练模式 BatchNorm 用于缓存。
原生基线验收还包括学习曲线、有效样本数和原论文/官方结果的差异说明。
复现容差与可接受指标偏差须在完整训练前锁定，不得因结果不佳事后降低标准。

## 10. 实施阶段与交付标准

### 阶段 A：数据和官方实现审计

固定三个官方代码提交与环境；完成全部任务清单、数据版本、结构/标签审计和 split hash。
为三个模型确定节点特征边界，记录原生模型配置及任何必要兼容补丁。
交付 manifest、任务覆盖表、模块 README 和环境记录。

### 阶段 B：原生模型与最小闭环

先以 CGCNN formation energy 建立第 0 轮，再跑第 1 轮训练、全库缓存及缓存/直接链一致性。
对 Matformer 和 iComFormer 重复该验收，测量 epoch 时间、显存、缓存体积与 IO 成本。
据实测值估算完整矩阵所需资源；如调整预算，先更新配置与记录。

### 阶段 C：全部任务第 0 轮

运行三 backbone 的完整任务清单，保存基线、划分、预测和原生复现记录。
任务或数据异常逐项处理，不能仅保留表现良好的任务。

### 阶段 D：完整循环与必要对照

按预设轮数和 seeds 运行逐阶段链及第 6 节必要对照。
Slurm 依赖顺序为 `train_r → cache_r → train_(r+1)`；
调度成功不代表缓存有效，下一轮仍必须验证完整 manifest。
不同 backbone/任务/seed 可按资源并行，同一条链严格串行。

### 阶段 E：统一评测与报告

完成预先约定的测试曲线、验证集轮数选择、相对改善热图及计算预算分析。
交付全部任务的完成状态、配置、checkpoint 链、来源和缓存 checksum；
若有未完成链，则报告为部分完成，不能宣布全任务实验完成。

完成标准是三个 backbone 的全部预定任务均得到可审计的基线和循环结果，
完整链一致性与冻结检查通过，必要对照可比较，所有失败有记录，MAE 曲线可重建。
是否观察到性能改善不作为工程验收的前提。

## 11. 运行环境与服务器约束

所有训练、推理、全库构图/缓存、批量评测和编译通过 Slurm 执行。
本地修改源码并提交；服务器只通过已确认 remote 的 `git pull` 同步源码。
每次连接前在 [gpu.md](../agents/gpu.md) 登记用途，连接后先检查仓库并按规范同步。
不得把旧实验作业 ID 或节点状态当作新任务当前资源，开始实施时重新核对。

各 backbone 使用任务专用 Python venv，安装前创建环境并在
[env.md](../agents/env.md) 记录 Python、PyTorch、CUDA、PyG/DGL 及依赖版本。
官方旧环境不能直接假设适配现有 GPU；先做依赖解析与小图 GPU 验证，必要源码编译走 Slurm。

数据与历史模型链优先放任务专用持久存储。`/dev/shm` 仅作可丢失的运行缓存，
不得作为全库特征和唯一 checkpoint 的长期存放位置；跨节点访问路径须先验证。
网络下载遵守 `AGENTS.md` 的显式代理和计算节点网络验证规则。

进度按提交粒度写入 [update.md](../agents/update.md)，当前快照与阶段变化写入
[state.md](../agents/state.md)，测试结果写入 [test.md](../agents/test.md)。
架构/环境经验写入 [lessons.md](../agents/lessons.md)，历史记录追加保留。
